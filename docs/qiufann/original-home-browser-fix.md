# 原小屋登录与记录连接修正

## 手机验收更新（2026-11-16，Asia/Shanghai）

本人先确认连接可用、北极星聊天实际读到原小屋记录，随后确认“可以写回”。据本人手机反馈，24 版读取与所做测试记录的写回均已通过验收；此前构建回执中的读取/测试写回待验收状态据此更新。此处记录本人验收，不冒充本开发窗口独立取得记录 ID 或写回回执，也不扩大为全部工具、并发/中断异常及所有网页登录路径都已逐项验收。

## 触发问题

22 版手机已确认启动进入原小屋，但 MCP 测试失败。先出现首页地址没有 `/mcp` 的校验错误；更正后提示会话未获接受，“打开原小屋并登录”却只打开首页，没有独立登录动作。原生实现把 401、403、重定向和登录 HTML 都归为未登录，反复点首页无法解决。

已有正式 Site 插件的真实只读请求成功，说明后台记录服务可用；这不能证明 Android 已连接。仅凭截图也不能断定所有 403 都是未登录。

## 修正

- “登录原小屋”进入 Sites 托管的 `/signin-with-chatgpt` 顶层登录入口，返回后自动发现工具并实际读取 `home_list`，读通后才允许启用。普通启动仍打开原首页，不强制每次重新登录。
- 首页地址或 `/mcp` 地址都自动规范化，旧首页格式连接可复用，保留禁用工具选项，不重复创建来源。
- 原生不再把取出的网页 Cookie 拼到独立 HTTP `/mcp` 请求。使用无原生 JS 接口的独立浏览器请求，让正常网页登录会话访问同一原站的生活记录接口；不设置假 User-Agent、访问者身份头或认证头。
- 原站增加 `/api/home/bridge` 最小无素材页面和 `/api/home/rpc` JSON 接口。所有访问要求 Sites 注入真实访问者身份；RPC 还要求精确同源 Origin、JSON 类型和 `X-Home-Action: 1`。保留当前私密访问范围，不使用免登录服务凭据，不伪造拥有者身份。
- 后台工具目录直接从原有实际工具定义筛选，生活记录走原数据库。只开放既有生活操作及已确认的只读记忆；不开放聊天原文归档、日记镜像、主记忆改写或恢复。GitHub、Notion、花园原连接保持独立。
- 浏览器自动携带会话，脚本不读取 Cookie；原生只在内部比较会话快照以防账号切换，不把凭证交给 JS、模型、日志或导出。只有精确同源桥接页可执行预置请求脚本；脚本再次核对页面来源/路径，并使用原生确认的绝对地址，不受网页 base 地址影响。无远程原生接口；跳到登录页会停止并提示本人登录。
- 请求有体积、时间及并发上限，不自动重试未知写入；403、404、非 JSON、超时分别显示安全结果。实际记录读取失败时不启用工具，不把目录或模拟数据当成成功。

## 小屋外观与原数据

本次原站源码仅修改后台路由并加入合成验证脚本，无数据库迁移。完整三页、头像、雪景/雨夜、排版和 29 个静态资源的 SHA256 在构建前后逐项相同。后台更新不重新绘制首页，不更换原网址或扩大访问范围。浏览器本地书籍、音频等边界仍见 [原小屋集成说明](original-home-integration.md)。

## 验证

- 合成内存数据库验证真实身份缺失、跨源/缺 Origin、缺动作头、非 JSON、过大请求均被拒绝；目录屏蔽聊天和主记忆写工具；原网页表单 ↔ 新浏览器接口共用记录，包含新增、版本更正、稳定编号回放及账号隔离。
- 原站既有生活记录回归通过；29 个原静态资源逐字节不变。
- 实际 Android 请求脚本的 Node VM 测试覆盖同源凭证处理、原样 RPC 正文、空通知回执、HTTP 拒绝、HTML/错误协议、响应体积和未知结果不重试，不进行真实网页登录或服务写入。
- 原生检查覆盖正确的托管登录入口、精确桥接页与来源限制；真实 WebView 登录、Cookie 会话接受、手机新增/回读仍需安装新版后验收。
- 本环境缺少 Sites 源码助手和可用的 Sites 浏览器 QA 接口。源码使用原项目的一次性授权在内存中完成拉取/推送和 SHA 校验，部署包仅含该提交的构建输出与原存储配置。没有为绕过限制另开浏览器或更换站点身份；不把脚本验证当成手机成功。

## 手机步骤

1. 覆盖安装本次个人签名更新，不卸载、不删除原连接。
2. 原小屋照常作为启动页。先进入聊天 → 请求 → MCP → 原小屋，点“测试连接”。
3. 若要求登录，点新的“登录原小屋”；在站点自己的 ChatGPT 登录页完成流程后返回。界面会自动测试一次实际读取，成功后保存。
4. 若明确 HTTP 403，保留状态并报告，不反复登录或提交写入。不要把密码、授权码、含认证参数的网址或 Cookie 发到聊天。
5. 连接成功后再以一条明确指定的测试记录验收双向写回；目前没有真实手机写入成功的结论。
