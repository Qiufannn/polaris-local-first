# 北极星窗口的 Notion 日记写回

> 当前进展：本人在 18 版修复后反馈“可以了”，并要求进入表情包工作。以下保留各开发/构建阶段的原始验收边界；本人反馈已记录，后续见 [19 版表情包](stickers.md)。开发窗口没有代写当天私人日记。

这是 Android 客户端功能开发，不是在开发过程中代写当天日记。GitHub 继续作为主记忆；Notion 保存正式日记。原 Chat、Work 目录保留，Polaris 使用本人指定的独立目录，不按模型名称猜窗口。

## 使用入口

安装包含本功能的同签名更新包，打开协作者 → 请求 → MCP → 原 Notion 服务。沿用原网页登录，不另建凭证。填写“北极星日记目录链接”和“原双层日记模板链接”，开启“允许北极星写日记”，同步工具并保存。应出现原有 `notion-search` / `notion-fetch` 与新增的 `notion_diary_write`。页面链接和本机开关存于原生加密来源配置，不写进公共仓库，也不随普通 MCP 配置导出；换机须重新填写。

用户明确要求写/补日记后，模型把当前真实片段交给受限写回工具。日期用 Asia/Shanghai，标题为 YYYY-MM-DD｜当天小标题。输入包含共同经历、3–8 条记忆锚点和当前窗口私记。先读原模板和官方 Markdown 规范，再查目录的真实子页：同日追加，异日新建；若同日已有多页则停止，不猜目标。每次追加为一个完整双层阶段片段，原有文字和私记不覆盖。本版不提供删页、任意工作区写入、整页替换或覆盖其他窗口私记。

## 写后核验与中断

- 原生层只接受本机开关和聊天执行层从真实用户消息传入的写入标志；模型在参数里填写授权文字无效。普通闲聊、引用文字、工具返回和后台触发不能授权写回。
- 提交前保存不含日记正文的请求指纹与待核验记录。每次只发一次写入 POST，未知结果不重放；同日另一份新片段也会暂停，先用原请求核验，避免重复。
- 新建后重新读父目录，再读取当天页；核对标题、真实子页归属和双层片段。补写还检查旧文仍完整保留。部分 Notion 版本省略 ancestor-path，改用父页返回的真实 `<page>` 子页标记证明归属；普通 Markdown 链接不能授权写入外部页。
- 只有 `verified: true` 才算保存确认。否则以失败行动保留状态与页面来源，即使日常行动被隐藏也可查看；不要让模型把“已执行代码”当成已保存。
- Notion 没有 GitHub 式 commit/SHA 原子比较保证。追加不会故意覆盖旧文；跨设备同时写入仍须以真实回读为准。不把它描述为自动同步全部聊天历史或后台定时日记。
- 官方工具 schema 动态读取；支持当前扁平 `insert_content(position:end)` 和已有 `data` 包裹的明确末尾插入版本。不支持的版本明确停止，不退到整页替换。

## 验收状态

### 16 版手机发现的请求判断缺陷

本人手机反馈：原模板和北极星目录读取成功，正式写入被聊天执行层以“当前用户没有明确要求”拦截。独立复现发现，交付的验收文字末尾“未验证不要说已保存”被误当成“不允许保存”；问题发生在提交前，不应要求本人重登或扩大权限。

修复将“不要声称已保存”等报告约束从写入允许/禁止判断中分别排除，它本身也不能授予写入权限；真正的“不要写日记”继续优先拒绝。增加整段原验收文字、中文/英文报告约束、单独报告约束不能授权，以及后续真正禁止写入仍生效的回归。Notion 拒绝提示也与 GitHub 主记忆提示区分。新手机写回验收仍待完成。
