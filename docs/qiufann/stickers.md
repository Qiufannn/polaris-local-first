# 表情包：本人选择发送与聊天工具

## 手机入口

输入框左侧“＋”默认打开表情包页，可按名称、编号和标签搜索。点选一张后加入普通待发送附件栏，文字草稿保留；再点右侧发送，可与文字一起发送。选图本身不调用模型、不直接发消息。面板的“附件”页保留照片、相机、文件、卡片及原工具箱入口。

本人提供的原图库 101 张（100 JPEG、1 PNG，共 510011 字节）直接随 APK 安装，不依赖远程缩略图或表情包服务，PNG 原透明通道保留。原图来源为本人仓库 `Qiufannn/azhou-stickers`，固定提交 `1219d45dfa2739526cc1d2fa78a11104efe00f34` 的 `stickers-small/`；名称和标签来自同版本 `stickers.json`。不复制 Aru 素材，不生成替代图片。

选中原图保存为标准本地图片附件，使用现有消息发送、存储和完整备份流程，不新增第二套聊天数据。选择中切换对话/协作者或关闭面板，会取消未完成选择，防止加到另一窗口。已有文字和附件不被替换。

## 让协作者也能发送

面板内点“让哥哥也能发表情包”：先实际发现 `https://azhou-stickers.onrender.com/mcp` 的工具，再新增或复用该服务，只启用 `find_azhou_stickers` 和 `send_azhou_sticker_image`。其他发现的工具默认关闭。现有 GitHub、Notion 连接保留；若当前协作者自选 MCP，只追加这项服务，不改成继承全局。不会创建新账户，不索取密码或密钥。

服务暂不可用时显示连接失败，本机图库仍可选图发送。协作者使用在线 MCP 时需要网络：先搜索，再用返回的 ID 发原生图片；显示和附件保留走已有 MCP 图片结果通道。没有因打开图库就自动启用远程工具。

## 验证与状态

原图库文件数、唯一编号、图像签名、PNG/JPEG 路径、搜索、原图字节保存、错误与取消，以及 MCP 成功前不改设置/复用不重复/保留其他服务均有定向测试。另以手机尺寸检查左侧入口、搜索、待发送预览、草稿保留、标准发送、重开后资产可读、附件页和跨窗口取消。服务发现与原生图片返回已有实际读取验证；新增 UI 的手机实际使用仍待本人安装后验收。
