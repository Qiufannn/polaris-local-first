# ChatGPT 连接失败排查

## 2026-11-16：共读请求后出现通用错误

本人截图显示：前一轮原小屋日历操作报告成功，随后询问共读和账本时只显示“ChatGPT 连接失败，请检查网络后重试；本地聊天仍保留。”。该提示来自原生 `ChatGptAuthPlugin.safeMessage` 的兜底，不足以判断是代理、DNS、TLS、超时、连接中断还是数据解析。不能据此要求重新登录，也不能宣称书籍上传或小屋后台故障。

已读取原小屋后台近期日志：未见本轮生活接口的服务异常，周围浏览器 RPC 请求返回 HTTP 200 / 202；这些 HTTP 状态不等同于所有工具业务操作已成功。此处无法读取本人手机的实际 ChatGPT 网络异常或账号状态，没有代替本人生成模型请求，没有手机屏幕操作。

本轮先修复错误信息不足的问题：

- 原生 ChatGPT 请求记录固定阶段：准备请求、更新授权、建立连接、发送请求、等待回复、识别回复、接收回复。
- 依据异常类型及有限层数的原因链区分 DNS、证书、TLS、连接失败、超时、中断、一般读写、JSON 数据与未知错误。证书校验照常启用。
- 只返回固定中文说明及 `CGP-类别-阶段` 编号，不输出原始网络异常、地址、账号、凭证、请求或响应正文。不额外上传诊断数据。
- 原有明确的额度、权限和流格式提示继续保留；网络异常不会清空登录。没有新增自动重发、付费回退或代理转发。
- 前端实际订阅传输验证：错误编号能保留至界面；中途错误时保留已收到的文字，只调用一次原生订阅请求，不转用通用线路。

## 安全连接兼容调整

本人随后实际反馈：普通聊天出现 `CGP-INTERRUPTED-WAIT`，读取模型出现 `CGP-TLS-GENERAL`，SakuraCat 全局代理也已试过仍失败。读取模型不携带共读原文或旧对话，因此后续优先检查原生到 OpenAI 的连接兼容性，而不是要求继续修改书籍或记忆设置。上述编号仍不能证明具体是服务端、节点还是客户端导致断线。

将 OpenAI 授权、刷新、读取模型与订阅回复的底层网络实现由系统 `HttpURLConnection` 改为专用 OkHttp 4.12.0：

- 支持通过正常 ALPN 协商 HTTP/2，兼容 HTTP/1.1；使用系统 DNS、代理选择和证书信任，保留主机名校验及现代 TLS，不伪造浏览器身份或访问者头。
- OpenAI 请求仍只允许 HTTPS、标准 443 端口及 `auth.openai.com` / `api.openai.com`，拒绝 URL 内凭证和片段。订阅路径固定为原 `/v1/responses`，没有改为其他付费或中转线路。
- 每次请求独立拥有连接池，完整读取并关闭响应后再取消和清理，下一次不会借用已被服务或节点关闭的旧闲置连接；不以零闲置连接池提前关掉仍在等 HTTP/2 结束帧的正文。关闭自动连接重试与跳转；POST 请求体标记为一次性，连 HTTP 408/503 + `Retry-After: 0` 也不能自动重放模型或旋转授权提交。原先针对明确 HTTP 401 的一次受控授权刷新仍保留。
- 保留流式消费、严格完成确认、按请求取消、账号切换检查、授权回复 1 MiB 上限和已有分阶段错误提示。原凭证存储与登录记录格式没有迁移，网页、小屋、记忆和书籍内容没有修改。
- 新增本机真实 TLS 测试：HTTP/2 中文/表情 SSE、HTTP/1.1 分块 SSE 与表单、无效证书/主机名拒绝、域名/地址边界、跳转拒绝、提交后断开不重发、408/503 不重放、下一次手动调用使用新连接、等待时取消、授权回复体积上限。只使用合成身份和回环服务；测试信任与回环 DNS/端口调整仅存在测试源码。

这是针对现有失败位置的兼容修复，手机实际恢复仍需安装后读取模型和普通聊天核对，不能用本机合成服务验证替代真实手机结果。
