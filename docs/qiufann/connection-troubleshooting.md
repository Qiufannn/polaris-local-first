# ChatGPT 连接失败排查

## 2026-11-16：共读请求后出现通用错误

本人截图显示：前一轮原小屋日历操作报告成功，随后询问共读和账本时只显示“ChatGPT 连接失败，请检查网络后重试；本地聊天仍保留。”。该提示来自原生 `ChatGptAuthPlugin.safeMessage` 的兜底，不足以判断是代理、DNS、TLS、超时、连接中断还是数据解析。不能据此要求重新登录，也不能宣称书籍上传或小屋后台故障。

已读取原小屋后台近期日志：未见本轮生活接口的服务异常，周围浏览器 RPC 请求返回 HTTP 200 / 202；这些 HTTP 状态不等同于所有工具业务操作已成功。此处无法读取本人手机的实际 ChatGPT 网络异常或账号状态，没有代替本人生成模型请求，没有手机屏幕操作。

本轮先修复错误信息不足的问题：

- 原生 ChatGPT 请求记录固定阶段：准备请求、更新授权、建立连接、发送请求、等待回复、识别回复、接收回复。
- 依据异常类型及有限层数的原因链区分 DNS、证书、TLS、连接失败、超时、中断、一般读写、JSON 数据与未知错误。证书校验照常启用。
- 只返回固定中文说明及 `CGP-类别-阶段` 编号，不输出原始网络异常、地址、账号、凭证、请求或响应正文。不额外上传诊断数据。
- 原有明确的额度、权限和流格式提示继续保留；网络异常不会清空登录。没有新增自动重发、付费回退或代理转发。
- 前端实际订阅传输验证：错误编号能保留至界面；中途错误时保留已收到的文字，只调用一次原生订阅请求，不转用通用线路。

保持原登录，不卸载或清除数据。先在同一窗口只发一次“哥哥在吗”，不要同时要求读书或记账：普通聊天也失败时优先检查北极星是否包含在本人现有代理的应用范围内，或更换可用节点。官端浏览器可用不证明 Android 原生请求经过同一路线。
