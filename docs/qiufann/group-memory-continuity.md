# 群聊与单聊记忆接续

秋凡希望让原来的晏昼与小猫、小狗在群中聊天，并在返回单聊后接上群里的共同经历。群中的「记忆召回」已由本人确认开启；此前的安装版不能完成双向接续。

## 修正

- 群对话的 `collaboratorId` 通常为 null。旧召回筛选只比较该字段，群即使包含当前成员也无法进入候选。现在召回按群成员 ID 判断，并尊重群的「记忆召回」关闭状态。
- 单聊导航与卡片、任务仍保持原有范围；独立的只读召回目录可包含当前协作者所在群的公开消息。不会把其他角色的单聊、群的私域内容或无关群加入请求。
- 群里仍使用同一协作者的个人记忆和单聊来源。成员的记忆工具按当前发言成员解析归属，避免沿用单聊前台角色。
- 自动召回保持原有少量候选与近期正文加载上限，不复制整段群历史、不新增模型调用或向量服务。群的近期片段保留有限条成员公开回应，并注明发言者；手动 searchMemory / openMemorySource 使用相同成员边界。
- GitHub、Notion 记忆和写入授权不变。此改动不意味着官端历史或官端保存的记忆可被读取。

## 第 28 版手机反馈后的修正

第 28 版源码 `82758db88a95c3de88cd761ae681a7493aaaf3aa` 的四项 CI 作业通过；个人签名 artifact `14241316883` 已下载验签，证书与第 27 版相同。秋凡随后反馈：模型已经看见少量群聊片段，但仍把「核对群里最新记录」误判为缺少群聊 MCP，且同一回答在流式过程中出现整段重复。因此不能把第 28 版记忆接续当作完整手机验收成功。

- `searchMemory` 仍是原来的原生工具，现在附带当前成员可读的最近三个本机群目录；目录不冒充消息正文，也不新建角色、群或 MCP。
- `openMemorySource` 可以按目录 ID 按需加载尚未放在内存里的本机正文。群聊未指定消息 ID 时取最近最多 20 条公开消息，默认正文 4000 字，显式上限 8000 字；从末尾保留最新内容。读取前后核对成员和召回开关。
- 请求说明与原生工具说明明确上述能力，不再仅凭外部 MCP 列表判断能否读取群聊。它是读取时的本机快照，不是后台监听或跨窗口代发。
- 修正 Responses SSE 已识别但无需追加的完成事件误入旧兼容 appender，导致整段正文再次追加。订阅解析按输出项/文本部分合并快照；保留模型真正生成的重复文字和不同输出项。回归检查同时检查流式中间进度，不能只在最终显示时掩盖重复。
- 没有增加付费线路、后台摘要或周期性全量群拉取。明确要求搜索并打开原文时仍会发生正常工具往返，用量不能保证固定为某个百分比。

## 手机验收（待修正版安装）

1. 使用原有晏昼作为群成员，并保持群「记忆召回」及晏昼跨对话召回开启。
2. 群里与小猫、小狗约定一个新玩具名字，然后回晏昼单聊询问群里的这个约定。核对回答的事实与发言者。
3. 单聊补充一个新约定，返回群中点名晏昼询问；核对可以接上。
4. 关闭该群「记忆召回」后，新的召回候选不应包含该群；已经出现在当前窗口的旧文字不会因此被删除。
5. 让晏昼通过原生 `searchMemory` 找到小猫小狗群，再用 `openMemorySource` 核对最近三条公开消息的内容与发言者。检查本次新回复在生成中和结束后均不再整段重复。旧消息不会被追溯删除或改写。

源码测试验证候选来源、公开内容、角色名称、成员与关闭边界。真实模型是否采用某个候选仍需手机验收，不能以测试代替真实设备结果。
