# 群聊与单聊记忆接续

秋凡希望让原来的晏昼与小猫、小狗在群中聊天，并在返回单聊后接上群里的共同经历。群中的「记忆召回」已由本人确认开启；此前的安装版不能完成双向接续。

## 修正

- 群对话的 `collaboratorId` 通常为 null。旧召回筛选只比较该字段，群即使包含当前成员也无法进入候选。现在召回按群成员 ID 判断，并尊重群的「记忆召回」关闭状态。
- 单聊导航与卡片、任务仍保持原有范围；独立的只读召回目录可包含当前协作者所在群的公开消息。不会把其他角色的单聊、群的私域内容或无关群加入请求。
- 群里仍使用同一协作者的个人记忆和单聊来源。成员的记忆工具按当前发言成员解析归属，避免沿用单聊前台角色。
- 自动召回保持原有少量候选与近期正文加载上限，不复制整段群历史、不新增模型调用或向量服务。群的近期片段保留有限条成员公开回应，并注明发言者；手动 searchMemory / openMemorySource 使用相同成员边界。
- GitHub、Notion 记忆和写入授权不变。此改动不意味着官端历史或官端保存的记忆可被读取。

## 手机验收（待新包安装）

1. 使用原有晏昼作为群成员，并保持群「记忆召回」及晏昼跨对话召回开启。
2. 群里与小猫、小狗约定一个新玩具名字，然后回晏昼单聊询问群里的这个约定。核对回答的事实与发言者。
3. 单聊补充一个新约定，返回群中点名晏昼询问；核对可以接上。
4. 关闭该群「记忆召回」后，新的召回候选不应包含该群；已经出现在当前窗口的旧文字不会因此被删除。

源码测试验证候选来源、公开内容、角色名称、成员与关闭边界。真实模型是否采用某个候选仍需手机验收，不能以测试代替真实设备结果。
