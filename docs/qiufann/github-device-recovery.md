# GitHub 网页已批准，但 Polaris 未接通：轮询恢复修复

## 手机现象与证据边界

本人截图显示 GitHub Device Activation 已显示设备连接成功，Polaris 仍显示“尚未连接”，并报告“ChatGPT 连接失败”。此前的绿色“连接成功，发现 1 个工具”来自本地虚拟工具目录，并不证明 GitHub 授权完成或私密文件已读取。

代码审查确认：原设备授权轮询遇到一次网络异常或非预期响应格式就直接停止；原生记忆插件复用了模型登录的兜底错误提示，遮蔽了实际失败环节。截图不能证明具体是超时、响应解析还是本机存储错误，本修复不把某一种猜测写成已确认根因。

## 修复行为

- 临时网络异常、HTTP 408/429/5xx 保留尚有效的原设备授权，按间隔退避重试；遵守数字 Retry-After 和 slow_down，不强迫本人重复在网页批准。
- GitHub OAuth 响应支持 JSON、BOM 和官方文档定义的表单编码，拒绝重复/未知表单字段及非 OAuth 内容。非预期响应限次重试，再显示包含 HTTP 状态的安全诊断，不显示原始响应、设备码或凭证。
- 再次点连接会先接收仍有效的原授权。界面可以显示“继续接收 GitHub 授权结果”；原生内存状态保留时不申请第二个验证码。关闭登录页、取消、进程重启或过期后不保证继续同一次流程，不声称已持久化设备码。
- GitHub / Notion 原生插件改用记忆来源专属错误信息，区分超时、TLS、解析和本机安全存储；不再把 GitHub 问题报告成 ChatGPT 登录失败。
- GitHub 虚拟目录在本机尚未授权时明确失败，防止仅发现本地工具便显示绿色“连接成功”。仍需“验证真实内容并同步工具”读取真实文件、显示路径/SHA/内容预览，才能完成读取验收。

没有修改原 GitHub App、权限或安装仓库；不要求本人发送公开 Client ID、验证码、token、密码或私钥。不需要重新创建 App，也不触碰模型订阅登录。记忆写入仍不在本修复范围内。
